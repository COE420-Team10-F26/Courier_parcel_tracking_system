# Exercise 3: Core Processes Matrix

### Required Format

| Process No. and Name | Input Data | Output Data | Rules | 
| ----- | ----- | ----- | ----- | 
| **P1 - Manage Accounts and Login** | Registration details (Customer), Login credentials (Customer, Field Staff, Admin), Staff account details (Admin), Account status change (Admin), User record (D1 Users) | New or updated user record (D1 Users), User list (Admin) | Registration is rejected if the email is already registered, a field is empty or the password is under 8 characters. Login only works when the email and password match an active account, a deactivated account cannot log in. The dashboard opened depends on the user's role. Only an admin can create staff or admin accounts and they get a temporary password that must be changed at first login. When the admin creates a field staff account, the admin also sets that staff member's zone (one emirate); zones are never assigned automatically. Deactivating an account keeps its parcel records. | 
| **P2 - Book Parcel** | Booking details: sender pickup address and emirate, recipient name, phone and address, parcel weight, dimensions and description (Customer), Customer record (D1 Users) | Parcel record (D2 Parcels), Booking confirmation and tracking number (Customer), Status history entry (D3 Status History) | Only a logged-in customer can book. The booking is not confirmed if a mandatory field is empty, the recipient's phone is not a valid UAE number (+971 followed by 9 digits), the weight is not more than 0 and at most 70 kg, or any dimension (length, width, height) is not more than 0 and at most 150 cm. Every confirmed booking gets a unique tracking number in the format CPT-XXXXXX, shown on the confirmation page together with the expected delivery window: 24 hours from pickup if the recipient is in the same emirate as the sender, 48 hours if it is in a different emirate. Once the booking is confirmed, the system automatically sets the parcel's status to Pending Pickup and adds a D3 entry (status, timestamp). | 
| **P3 - Assign/Monitor Parcels** | parcel assignment (Admin); parcel records, including last update time (D2 Parcels); field staff accounts (D1 Users) | Assigned pickups and deliveries, assignment notification (Field Staff); parcel list, delay alert (Admin); updated parcel record with assigned staff (D2 Parcels); status history entry (D3 Status History) | Only a logged-in admin can assign parcels, and only confirmed bookings can be assigned to active field staff accounts. Reassigning is allowed only before pickup. Assigning sets the status to Assigned, updates D2, adds a D3 entry (status, timestamp, admin) and notifies the field staff member. P5 then sends each parcel's customer an Assigned status notification (FR-09). An undelivered parcel with no status change for 48 hours is set to Delayed, a D3 entry is added and an alert goes to the admin. | 
| **P4 - Update Parcel Status** | Status update (Field Staff), Pickup confirmation (Field Staff), Proof of delivery: recipient name/signature/ID (Field Staff), Parcel records (D2 Parcels) | Updated parcel record, including pickup time and proof of delivery (D2 Parcels), Status history entry (D3 Status History), Status change (to P5) | Only a logged-in field staff member can update a status, and only on parcels assigned to them, from their assigned task list. Statuses move forward in specific order: Assigned -> Picked Up -> In Transit -> Out for Delivery -> Delivered. Skipping a step or going backwards is not allowed. The only exception is a failed visit: it is recorded as Attempted with a mandatory note and the parcel goes back to Out for Delivery for a retry, which is the only case where the status moves back a step. A parcel has at most 3 delivery attempts; after the 3rd failed attempt its status becomes Returned to Sender. Confirming pickup changes the status to Picked Up and records the pickup time. A parcel can only be marked delivered after the proof of delivery is captured. Every status change updates the parcel's current status in D2 and it also creates a time stamp entry in D3 containing the status along with the timestamp and the responsible actor/location. P4 does not send the notification itself. It passes the status change to P5, which reads the status history in D3 and sends the notification to the customer. | 
| **P5 - Tracking and notifications** | Tracking number (Customer); Parcel ID (Admin), for tracking history lookup; Status change (from P4); Parcel record and status history (from Parcel / Status History data stores) | Parcel status and history (to Customer); Status notification (to Customer); Parcel tracking history (to Admin) | 1. Tracking number must exist, otherwise the customer gets a "not found" message and nothing else is shown. 2. A customer sees only their own parcels. 3. Admin can view the full tracking history of any parcel by Parcel ID. 4. History is shown in chronological order, each entry with status, date/time and location or staff. 5. A Status notification is sent to the Customer on every status change recorded in D3 (FR-16): Pending Pickup from P2, Assigned and Delayed from P3, and Picked Up, In Transit, Out for Delivery, Attempted, Delivered and Returned to Sender from P4. 6. Each notification is sent once per status change, no duplicates. 7. Read-only: P5 never changes the parcel status. |
